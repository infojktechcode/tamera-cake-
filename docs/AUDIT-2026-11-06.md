## CRITICAL

### C1 — Build fails: `"use cache"` module imports non-cached function
**File:** `src/lib/catalog.ts`  
**Error:** `Module "src/lib/catalog.ts" uses "use cache" directive but imports "findBestFlavourMatch" from "src/lib/catalog.ts" which does not have the "use cache" directive.`  
**Root cause:** Top-level `"use cache"` on a module that also exports a regular function.  
**Fix (committed `570b68a`):** Moved `findBestFlavourMatch` to `src/lib/flavour-match.ts` (no `"use cache"`), updated 3 importers.  
**Verification:** `pnpm typecheck` exit 0, `pnpm test` 379/379, build compile phase ✅.

### C2 — Settings save *always* throws validation error
**File:** `src/app/admin/settings/actions.ts` → `updateSettings()`  
**Root cause:** `FormData.get()` returns `null` for absent fields. Zod v4 `.optional()` accepts **only `undefined`** — `null` fails.  
**Reproduction:** The 4-field `SettingsForm` (only `whatsapp_number`, `daily_cake_limit`, `deposit_percent`, `min_lead_days`) omits `sms_provider` → `safeParse` fails → every save throws.  
**Two related coercion bugs:**
| Schema | Input | Result | Effect |
|---|---|---|---|
| `z.coerce.boolean().optional()` | `null` (absent) | **OK `false`** | SMS silently disabled on every save |
| `z.coerce.boolean().optional()` | `"off"` | **OK `true`** | SMS cannot be switched off |

**Fix (committed `c63e215`):**  
- New helpers: `field()`, `numberField()`, `checkboxField()` — normalise `null` → `undefined` ("not provided"), treat empty numeric as not provided, read checkbox state via last-value-wins (hidden `off` + checkbox `on` reports checked).  
- Changed `sms_enabled: z.boolean().optional()` (dropped `.coerce`).  
**Verification:** 10 new tests covering the exact SettingsForm payload, both SMS coercions, empty numerics, JSON parsing, authorization, validation boundaries. Reverting *only* `actions.ts` fails **7/10** tests. Full suite **389/389**, typecheck ✅.

## HIGH

### H1 — SMS is dead and unconfigurable
**Files:** `src/lib/notifications/service.ts` (lines 27-37), `src/components/admin/SettingsForm.tsx`  
**Evidence:**
- `sendSMS()` is a stub that `console.warn`s and returns `true` — no provider integration.
- `SettingsForm` exposes **only 4 inputs** — no `sms_enabled`, `sms_provider`, template, or credentials fields.
- `settings.message_templates` (JSON) exists in DB/schema but is never read; messages are hardcoded in `triggers.ts`.
**Impact:** Cannot send order confirmations, OTP, or marketing SMS. Africa's Talking / Twilio / other provider not plumbed.

**Impact:** New dev / CI environments fail to start or seed.

### M2 — Hardcoded SMS text vs `settings.message_templates`
**File:** `src/lib/notifications/triggers.ts`  
**Evidence:** `notificationMessageFor()` and `TEMPLATE_FOR_STATUS` are hardcoded; `settings.message_templates` column (created in migration 0012) is never queried.

### M3 — Template mapping wrong wording
**File:** `src/lib/notifications/triggers.ts:53`  
`TEMPLATE_FOR_STATUS.cancelled = "product_update"` — wrong semantic; should be a dedicated cancellation template or `"order_cancelled"`.

### M4 — No outbox retry / cron
**File:** `src/lib/notifications/outbox.ts` (if exists) / `vercel.json`  
**Evidence:** `notifications_outbox` table has `attempts` / `max_attempts=3` columns, but only `attempts: 1` is written on insert. No `vercel.json` cron, no scheduled job, no retry logic. Failed sends are never retried.

### M5 — `void notify(...)` swallows errors
**Files:** `src/lib/notifications/triggers.ts` (lines 84, 109, 124, 141)  
**Pattern:** `void notifyCustomer(...)`, `void notifyAdmin(...)` — fire-and-forget without `try/catch`.  
**Fix:** Wrap in `after()` (Next 16) so errors surface in logs and don't block the response.

### M6 — Rate-limiter Map never evicts, per-instance on serverless
**File:** `src/lib/rate-limit.ts` → `createRateLimiter()`  
**Evidence:** In-memory `Map` grows unbounded; each serverless invocation gets a fresh instance (no shared state).  
**Fix:** Use Redis / Upstash / Vercel KV with TTL, or at minimum add a size cap + periodic sweep.
